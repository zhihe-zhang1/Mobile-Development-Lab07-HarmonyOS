# 一、需求分析与验收标准

## 1. 项目背景

商品服务台为课堂练习用的 HarmonyOS 原生 App，帮助用户浏览商品、搜索、查看详情以及保存收藏；同时用统一界面演示 Mock 与真实 HTTP 的差异、请求异常处理和离线恢复。项目**不提供真实交易、支付或订单功能**。

## 2. 目标用户与用户故事

- 体验者：希望不登录即可查看商品，在网络不可用时也能通过 Mock 或缓存展示页面。
- 收藏用户：希望收藏商品后，关闭应用再次打开仍能找到收藏。
- 开发/测试者：希望验证 Loading、Success、Empty、Error 四种状态，并看清数据来源。
- 评审者：希望页面、组件、状态、服务的责任可区分，并具备可执行的验收步骤。

## 3. 功能需求

| ID | 优先级 | 描述 | 验收标准 |
| --- | --- | --- | --- |
| F01 | P0 | 商品列表 | Mock 模式展示 5 件商品，含编号、分类和价格 |
| F02 | P0 | 真实 API | 点击真实网络调用 `GET /products?limit=12`，成功显示实际返回商品，不伪造结果 |
| F03 | P0 | 异步状态 | 等待→加载中；非空→成功；空数组→空态；异常→失败及提示 |
| F04 | P0 | 搜索 | 按名称、分类、编号过滤，空筛选有提示 |
| F05 | P0 | 路由 | 进入详情；保存并返回时带回正确商品 ID、收藏布尔值 |
| F06 | P0 | 收藏 | 加入/取消收藏，通过 `put + flush` 持久化；重启后可恢复 |
| F07 | P0 | 本地缓存 | 成功列表保存公开信息，失败时可打开缓存 |
| F08 | P0 | 来源标注 | 明确显示「本地 Mock」「DummyJSON 真实接口」「离线缓存」 |
| F09 | P1 | 并发安全 | 快速切换数据源，旧请求不会覆盖最近一次结果 |
| F10 | P1 | 三类测试按钮 | 本地 Mock、空列表、模拟错误，均不触发真实请求 |
| F11 | P1 | 输入校验 | 无效路由参数及数据字段格式不能使页面崩溃 |

## 4. 非功能需求

- **稳定性**：失败可以重试；异常不会静默呈现空列表或伪造成功。
- **易维护**：页面层不解析 HTTP JSON，组件层不读写 Preferences，状态层统一编排请求与收藏。
- **体验**：文案区分 Loading、Empty、Error；使用 Scroll 确保小屏能够浏览完整列表。
- **隐私**：只保存公开商品数据和收藏 ID；不保存口令、Token 或定位信息。
- **性能**：Mock 仅 5 件；真实接口 limit=12；缓存至多保留 80 件，避免无限累积。
- **可复核**：Mock 数据、真实 API 和验收步骤在文档中可追踪。

## 5. 范围边界

本次不做账户体系、后台管理、支付和真实商品库存维护。DummyJSON 提供的内容属于第三方演示数据，不能视作商家报价。HAP 签名与设备运行依赖开发者本机 DevEco Studio 环境。
