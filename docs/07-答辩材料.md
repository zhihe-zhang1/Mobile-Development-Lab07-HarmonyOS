# 七、答辩演示材料（约 5–7 分钟）

## Slide 1｜项目概览（40 秒）

名称：实验七·商品服务台。目标是在 HarmonyOS 原生 App 中完成布局、列表、事件、导航、异步请求和收藏持久化，形成可维护的四层工程。

**演示**：打开运行中的 App，指明顶部数据来源与底部 Tab。

## Slide 2｜需求与原型（50 秒）

讲解商品浏览、搜索、详情、收藏和网络异常处理。打开 `docs/prototype.html` 展示静态原型，并说明原型与实际 App 的区别。用 T03/T04/T05 对照 Mock、Empty、Error。

## Slide 3｜四层结构（60 秒）

展示 `docs/02-系统架构.md` 关系图和代码目录。关键说明：页面层不直接请求网络；组件层不耦合业务服务；状态层维护请求版本和持久化；服务层统一真实/Mock Gateway 契约。

## Slide 4｜运行功能（90 秒）

1. 点击 Mock 商品：等待后看到成功列表与来源标注；输入“文具”过滤。
2. 点击耳机：进入详情；切换收藏；点击保存返回；切到收藏 Tab。
3. 切换空列表和模拟失败：清晰展示状态；若网络可用，再展示真实接口。
4. 结束应用进程并重新打开：查看是否恢复收藏。

*演示时必须说明 Mock 是模拟数据，真实接口可能受网络状态影响。若某一步失败，应展示真实失败情况而不是播放伪造画面。*

## Slide 5｜接口先行与团队协作（50 秒）

展示 `ProductGateway` 契约、`MockProductGateway`、`HttpProductGateway`。说明先约定字段和错误语义，两个实现可并行开发。用 `.github/pull_request_template.md` 解释 feature review 的检查点；实际团队记录按真实 PR 填写。

## Slide 6｜工程伦理、测试与总结（60 秒）

- 不冒充 Mock 结果为真实网络；错误状态如实显示。
- 不持久化密码、Token 等敏感信息。
- 明确标注数据来源，并区分真实网络、Mock 与离线缓存。
- 讲清哪些检查已完成、哪些需要 DevEco Studio 实测。

**可能提问：**

- **为什么需要 Store？** 页面只接收状态快照；请求竞态、缓存和收藏归到一起，减少重复实现。
- **为什么要区分 Empty 和 Error？** 空列表说明请求成功但没有商品；Error 表示服务失败，用户操作不同。
- **Mock 的用途是什么？** 在 API 尚未可用时并行开发 UI 与测试状态，不替代正式验收。
- **为什么不用 @State 直接改内部字段？** 本项目整体替换 `CatalogSnapshot`，便于追踪变化和触发 ArkUI 更新。
- **持久化何时算成功？** `Preferences.put + flush` 都完成，才更新收藏并向用户显示成功。
